About the model

How mill data reaches the assistant: sources and reports, import, storage, the tools the model can call, and the models behind it.

Information flow

Mill sources are imported, tagged to a machine position and stored in Supabase. The orchestrator answers through a fixed set of read-only tools, so the model behind it can be swapped. Ground rules

Every row has a positionBUS items, WOs, RCFAs, Bonvoy rows and document chunks all carry a position id from My Machine. That key is what lets an outage brief pull everything for "2nd press felt".
Reports in, tables outA report is stored once as written and extracted into tables. Pages and the assistant read the tables, and every number links back to the report it came from; nothing re-reads report text to count.
Tables first, search secondAnything with rows and columns goes in a table and is answered with a query. Only narrative text (report findings, RCFA write-ups, manuals) is chunked and embedded for search.
Pi in summariesThe assistant gets daily or hourly Pi summaries for the tag and window it asks for, not raw points. The demo stores them; at the mill they’ll be read from the historian on demand.
Models are swappablePrompts and tools live in this app, not in a vendor's features. The adapter maps one request format to each provider; embeddings record which model made them.
Answers cite recordsStatements carry the WO, report, RCFA, BUS day or Pi tag they came from in brackets, and the tools’ evidence is shown under each demo answer, so it can be checked before it goes on an outage plan.

How The Paper Mill generates Sim Mill’s data

The game’s simulation is stripped to a headless engine that runs the mill year as its historian (grades, breaks, upsets, failures and the process tags); the Python model adds what the game doesn’t have and writes the year out as the files a mill would send. They go in through the same importers and ingest as real data, so everything the assistant and the data pages read about Sim Mill came this way.

Existing path (same as real mill data)Added for Sim MillCheck that holds it to the step before
  1. Strip the game. On the-paper-mill’s sim-headless branch the 3D view, sound, panels and game systems (seasons, survival, leaders, civics, event cards, joke upsets) are left out; 34 of 116 source files run in Node. The full headless build replays 3 sim days to exactly the browser’s numbers.
  2. Run the engine as the historian. headless/historian.js runs 426 days (Sep 1 warm-up to Oct 31) on Sim Mill’s calendar (20 h outages every 6 weeks at 6 AM), with the game’s season-tuned failure rates stretched to a year. It writes the hourly running value of every DCS tag and the event log (grades, sheet breaks, upsets, failures, outages) to tools/sim-mill/engine/.
  3. Build on it. tools/sim-mill (Python) takes the engine’s grades and stops, and drives 27 of the 47 PM1 tags from the engine (config/tags.yaml). It adds what the game doesn’t have: instrument noise, bearing vibration and Uhle vacuum, the life of every fabric, felt, plate and roll, five planted faults, and about 30 developing failures a year (degrade.py: felts filling, showers plugging, pumps and syphons wearing, bearings, instrument drift). Each shows on its Pi tags for days or weeks and is caught and fixed, or missed and ends in a stop. validate_ref.py holds it to the engine’s reference year.
  4. Write the mill’s files and reports. Daily BUS sheets, JDE and Planner exports, the RCFA log and write-ups, Pi and Bonvoy, vendor PDFs, position runs and the last week of Bonvoy Reports. A Shift Report for every shift and a Production Report (Quality / Uptime / Tonnage / OME) for every mill day go through the report lifecycle (tools/reports), the same one a live report would take. Plus My Machine, Outage Planning, Consumables and task-package records.
  5. Load it like real data. load.py and the importers send everything through the token-guarded mm-llm-ingest into the org’s tables, files and embeddings; the reports are then extracted into downtime and production and indexed.
  6. Read it. The assistant’s tools, the 16 Sim Mill demo questions (37 checks), and the Daily Journal, Downtime / RCFA, Vendor Reports and Bonvoy Report pages. Every 6 weeks the year rolls forward a cycle.
