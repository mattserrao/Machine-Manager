# Migrations for an existing project

`../schema.sql` is the end state and builds a new project in one go. An existing project
(the live `machine-manager` project) moves to it in these steps, in order (steps 02–03, the one-off copy from the first Whiteboard's tables, are done and removed). Each file is
safe to run again.

| Step | When | What it does |
|---|---|---|
| `01-review-fixes.sql` | Any time (applied 2026-11-07) | `mm_apply` saves each change on its own, locks rows in id order, checks its input and can bring back a deleted record; adds `mm_file_refs`, `created_by`, an index for catch-up fetches and the nightly purge of old deletes. Works with both the old and new pages. |
| `../llm.sql` (step 04) | Any time (applied 2026-11-08) | MM LLM: the `llm` schema (equipment, BUS lines, WOs, actions, RCFAs, Bonvoy, packed Pi series, documents and searchable chunks with embeddings), ingest tokens, the `mm_llm_*` tool functions, and public demo orgs (`mm_llm_set_public`; Demo Mill is public). Only adds things; `mm_records` is untouched. The same file is the end state, so it is applied directly rather than copied here. |
| `05-sim-mill.sql` | Any time after step 04 (applied 2026-11-08) | Sim Mill: `llm.downtime`, `llm.production_daily`, `llm.position_runs`; the ingest also loads `records:mymachine` / `records:outages` / `records:consumables` for the token's org; `mm_llm_public_org` lists every public org (Demo Mill stays first); `mm_llm_summary` and `mm_llm_position_history` cover the new tables; new tools `mm_llm_downtime`, `mm_llm_downtime_summary`, `mm_llm_repeat_stops`, `mm_llm_rcfa_status`, `mm_llm_position_life`, `mm_llm_production`, `mm_llm_documents`, `mm_llm_bus_day`. Only adds; the same statements are in `../llm.sql` (end state). |
| `06-demo-sim-mill.sql` | Any time after step 05 (applied 2026-11-08) | Sim Mill becomes the only demo: `mm_demo_org` and `mm_demo_records` let signed-out visitors read the public demo org's My Machine, Outage Planning, Consumables and task-package records (read-only, no user ids). Access was switched with the admin functions: `mm_llm_set_public('Demo Mill', false)` (data kept), `mm_add_member('Sim Mill', 'demodemo@gmail.com', 'viewer')`, `mm_llm_grant_query('demodemo@gmail.com', 'Sim Mill', 40)` and `… 'Demo Mill', 0)`, and demodemo's Demo Mill membership removed. PM1 untouched. |
| `07-bonvoy.sql` | Any time after step 06 (applied) | Envoy is renamed Bonvoy: `llm.envoy` and its index and policies are renamed in place (rows kept); then apply `../llm.sql`, which re-creates the functions under their new names and adds the Bonvoy reports table, its functions and the Pi tag links. |
| `08-grade-hours.sql` | Any time after step 05 (applied 2026-11-08) | `mm_llm_grade_hours`: hours run on each grade from the production feed, so the assistant can compare grades per 100 h run. Read-only, only adds; also in `../llm.sql`. |
| `09-reports.sql` | Any time after step 08 (applied) | Reports and the report lifecycle: `llm.report_types`, `llm.reports` (as written, full-text searchable), `llm.report_events` (every status change); `report_id` on `llm.downtime` and `llm.production_daily`, plus saleable / broke / cull tons, off-spec hours and the OME parts; the ingest accepts `report_types` and `reports`; `mm_llm_process_reports` (service role) extracts and indexes them; read tools `mm_llm_reports`, `mm_llm_report`, `mm_llm_report_status`, `mm_llm_efficiency`; `mm_llm_downtime` also returns `report_id` (dropped and recreated); `mm_llm_summary` counts the reports. Then deploy `mm-llm-ingest` (new `process` action) and `mm-llm-ask` (tools `shift_reports`, `efficiency`) and reload Sim Mill. Also in `../llm.sql`. |
| `10-rag.sql` | Any time after step 09 (applied 2026-11-09) | Drop-in documents for the RAG: `llm.documents` gains a lifecycle (`uploaded → parsed → needs_review / accepted → indexed`, or `rejected` / `failed`), SHA-256, uploader, quality score and versions; new `llm.doc_pages`, `llm.document_events`, `llm.rag_jobs`, `llm.rag_settings`; HNSW index on chunk embeddings; storage policy so any member uploads PDFs to `<org>/rag/inbox/` of a **private** org (public demo orgs refuse uploads); `mm_rag_register`, `mm_rag_review` (editors), read tools `mm_rag_library`, `mm_rag_status`, `mm_rag_document`, `mm_rag_pages`, `mm_rag_search` (hybrid, RRF); worker functions for the service role; `mm_llm_documents` lists indexed documents only. Daily upload limit 100 MB per org, 30 MB per file. Admin, done: `mm_add_member('Demodemo RAG', 'demodemo@gmail.com', 'editor')` (private org for upload tests). Also in `../llm.sql`. |
| `11-rag-worker.sql` | Any time after step 10 (applied 2026-11-09) | What the RAG worker, page and MCP server need: `mm_my_orgs` (the signed-in user's orgs with role and public flag), `mm_rag_job_context`, `mm_rag_add_pages`, `mm_rag_requeue` (parse large PDFs in page batches), `mm_rag_give_up`, `mm_rag_chunks_to_embed` (service role); enables `pg_net`. Then deploy `mm-rag-process` and schedule it with pg_cron every 15 s (SQL in the file's header). Also in `../llm.sql`. |
| `12-file-size.sql` | Any time (applied 2026-11-10) | The `mm-files` bucket takes files up to 30 MB (was 25 MB), matching the RAG upload limit. Also in `../schema.sql`. Then redeploy `mm-llm-ingest` (its own file check moves to 30 MB). |
| `13-oauth-read-only.sql` | Before turning on the OAuth server (**not applied yet**) | Connected apps (MCP sign-in) are read-only: `private.is_oauth_client()`; editor / admin checks, RAG uploads and live MM LLM questions are refused for OAuth tokens. Your own sessions are unchanged. Also in `../schema.sql` and `../llm.sql`. |
